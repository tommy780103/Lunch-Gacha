# 本人限定サイトへの移行

2026年11月12日（日本時間）、ランチガチャの画面と検索APIを同じCloudflare Workerへまとめ、本人だけが利用できる構成へ変更しました。

## 実装

- 既存Workerを維持し、公開資産13点だけを専用publicディレクトリへ生成するスクリプトを追加。
- Static Assetsで画面を配信し、検索パスは既存Workerへ渡す。
- 許可Originを新サイトへ合わせ、同一Originの検索だけにAccess認証Cookieを送る。
- 本番・プレビューを含むWorker全体へCloudflare Accessを適用。再利用可能なAllowポリシーは本人のメール1件だけを許可し、Bypassは設定していない。
- プレビューURLを設定ファイルでも無効化。
- 旧GitHub Pagesは配信停止。リポジトリ・ソースは維持。
- 検索無効設定、既存Google Secret、同じSQLite Durable Objectのカウンターを維持。検索機能の有効化は行っていない。

## 検証

- 既存テスト33件成功。
- 資産生成後、異なる作業ディレクトリからのdry-run成功。
- ローカルWorkerで全13資産の内容一致、検索503、非公開ファイル3種類の拒否を確認。
- 本番デプロイ後、未認証の画面・JavaScript・CSS・画像・検索POST・偽装認証ヘッダー付きPOSTの6ケースがAccessログインへ転送された。
- 本番設定でGoogle Secretの型、検索無効、DO名前空間が変わっていないことを確認。
- ブラウザーでCloudflareのログイン画面を確認。本人による認証後の実機操作は未確認。

初回に追加した自動buildコマンドは、Wrangler 4.160.0が呼出し元の作業ディレクトリで実行したため失敗しました。build.cwdも設定ファイル相対にはならないため、自動build設定を外し、READMEの資産生成コマンドを先に実行する手順にしています。

## 運用

新サイトは[本人用ランチガチャ](https://lunch-gacha-search.choi-tool.workers.dev/)です。ログイン画面のCloudflareを選び、許可された本人アカウントでログインします。

GitHub Pagesを再有効化すると、認証のない旧画面が復活するため、公開元として再設定しないでください。サイト・APIへのアクセス制限はCloudflareの設定で管理します。ソースの公開・非公開とは別の設定です。
