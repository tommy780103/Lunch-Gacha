# 本人用サイトのGoogle店舗検索を有効化

2026年11月12日（日本時間）、利用者の依頼に合わせ、本人用サイトのGoogle店舗検索を有効にする設定へ変更しました。家族共有は今回の変更に含めません。

## 設定変更

- 画面の検索先を同じWorkerの検索APIに設定し、画面側の店舗検索を有効化。
- サーバー側の検索スイッチを有効化。
- Google APIキーは既存のWorker Secretを継続使用。値の取得・表示・ローカル保存は行わない。
- Worker名、Durable Objectクラス・バインディング・名前空間・移行タグ・共有上限の処理は変更しない。
- 全利用者合計で1日20回・月600回の上限、米国太平洋時間での更新、失敗時にも回数を消費する仕様を維持。
- Cloudflare Accessの本人限定設定と、GitHub Pagesの停止を維持。

```javascript
window.LUNCH_GACHA_CONFIG = Object.freeze({
  searchEndpoint: 'https://lunch-gacha-search.choi-tool.workers.dev/search',
  placesEnabled: true
});
```


## 本番初回検索と互換性修正

有効化の本番反映後、認証済みの初回検索はHTTP 503のNETWORKエラーとなり、日・月の共有カウンターをそれぞれ1回消費しました。失敗した予約を払い戻さず、カウンターは維持しています。

原因を調べたところ、Googleへの通信に指定していたリダイレクト拒否モードがWorkersでは未実装でした。[Cloudflare公式Request仕様](https://developers.cloudflare.com/workers/runtime-apis/request/)に記載のとおり、リクエスト構築時にTypeErrorとなります。サーバーの指定をmanualへ変更し、既存の非2xx応答判定で3xxも拒否します。これにより転送先へAPIキーを送らず、追加通信や自動再試行を行いません。ブラウザ側のリダイレクト設定は変更していません。

```javascript
redirect: 'manual'
```

- インストール済みMiniflare 5.20261110.0-beta / workerd 1.20261110.1、互換日2026-11-11で秘密情報を使わずRequest構築だけを実行。変更前のerrorはTypeError、変更後のmanualは構築成功を再現。Googleへの通信は行っていない。
- 修正後は既存33件と新規回帰1件、合計34件のテストが成功。301・302・303・307・308の応答について、Locationへ転送しないこと、HTTP 502を返すこと、日・月の予約1回を維持することを確認。
- 修正後のWrangler 4.160.0のdry-runが成功。共有上限・Durable Object構成・検索有効設定・秘密情報は変更していない。

## 停止方法

サーバー側の検索スイッチを無効にして再デプロイします。画面側も無効にする場合は設定変更後に静的資産を再生成します。共有カウンターの削除やWorkerの作り直しは不要です。

```toml
SEARCH_ENABLED = "false"
```
