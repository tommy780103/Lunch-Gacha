# 複数ジャンル検索と1kmの初期距離

## 要件と仕様

お店検索の複数ジャンル選択に対応し、店舗カードに検索ジャンルを表示する。距離の初期値はHTML・フロントの既定値・サーバーの省略時既定値をすべて1kmへそろえる。明示した距離は維持する。

ジャンルはトグルで複数選択でき、自由入力も追加の検索語として使用できる。空白と同一の語、既存の別名変換で同じになる検索語は1件にまとめる。ガチャからの選択は従来どおり単一ジャンルへの置換とする。

選択ジャンル数と使用する検索枠（最大N回分）を実行前に表示する。位置情報は1操作で1回だけ取得し、各ジャンルを既存APIへ直列に送信する。エラーや上限で残りを停止し、成功済みの結果は部分結果として残す。未実行と該当なしを区別する。検索条件が途中で変わった場合は後続リクエストを止める。

APIの1リクエストにつきGoogle1回、送信前の永続予約、失敗時の消費、全利用者合計の日20回・月600回を維持する。保存先のDO・識別子・キーとAccessを変更しない。古い画面の回数によって初回検索を誤って拒否せず、サーバーの上限チェックを権威とする。

## 結果の統合

各Google応答の条件一致候補を最大20件保持し、Place IDで重複統合する。先にジャンル別10件へ絞ると別のジャンルのラベルが欠けるため、検索ジャンルと帰属を結合した後に全体を最大10件へ絞る。評価・口コミ・距離の並び替えは既存と共通の処理にする。

ラベルは「検索ジャンル」であり、Googleの公式カテゴリを推定して付けるものではない。複数の検索で見つかった同一店舗には複数のラベルを付ける。元の結果データは変更しない。

## 検証

- 自動テスト67件が成功（バックエンド25、検索UI33、複数ジャンルの共通処理5、ルーレット4）。重複店舗のジャンル結合、候補統合後の10件制限、別名の重複除去、部分結果、途中失敗・上限停止、古い回数表示、条件変更中の後続停止を検証した。
- 静的資産13点の生成とWrangler dry-runが成功。本番の最終Workerバージョンは `bc28e494-4282-4d7f-bd4d-a5e723a003ac`。
- 本番で「うどん」「ラーメン」、初期距離1kmを使用し、高松駅周辺の模擬位置で実検索。各ジャンルのPOSTがHTTP200になり、検索ジャンル付きの10店舗を表示した。
- 検証では検索枠を2回使用。表示は月9回使用から11回使用へ更新し、検証終了時点は月残り589回・日残り9回。回数の保存先や上限は変更していない。
- 多数選択時の通常Googleマップ検索リンクは、各検索語を正規化した後に結合する。全体を80文字で切り落とす処理を避け、13プリセット＋自由入力でも末尾の検索語が残ることをテストと本番DOMで確認した。このリンク確認ではGoogle検索を追加していない。
- 検証用の模擬位置指定は解除した。MacとChromeの位置情報許可は、利用者の既存指示どおり維持した。
